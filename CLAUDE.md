# CLAUDE.md: Agent Platform

Coding-agent guide for this repository. Read this before writing any code. For lookup protocol, layer rules, testing/error conventions, and extension guidance, the primary authority is `AGENTS.md`, this file only adds current-state context and near-term priorities on top of it.

## Quick orientation

- **`AGENTS.md`**, architecture, layer rules, testing/error conventions, extension guidance (authoritative)
- **`src/agent_platform/README.md`**, layer map and known issues
- **`src/agent_platform/<layer>/README.md`**, local patterns for that layer; read before touching it

## Current state (as of 2026-07-30, the `Credentials`/`ClientOptions`/`RequestOptions` split (Phases A/B, described below) was extended to the 6 remaining network-bound domains that Phase B had deliberately left un-adopted: `reranking`, `translation`, `ocr`, `speech_to_text`, `vector_store`, `image_generation` (Phase C). Each domain's shared `core/interfaces/<domain>/config.py` config now inherits `RequestOptions`, and every network-bound provider gained a `client_options: ClientOptions | None = None` constructor param alongside `credentials`, wired wherever the vendor SDK's constructor actually accepts the equivalent kwarg (verified per-SDK rather than assumed): `reranking/{cohere,voyage}` accept `base_url`/`timeout`/`max_retries` directly; `reranking/jina` (raw `httpx`) gained a `base_url`+relative-path refactor and `timeout`, no `max_retries` (httpx has no client-level retry-count knob, `@with_retry()` already covers it); `translation/azure` wires `retry_total`/`connection_timeout`/`read_timeout` via `TextTranslationClient`'s azure-core `**kwargs`; `translation/deepl` only gets `base_url` (via `server_url`), since DeepL's SDK exposes no timeout/retry configuration anywhere in its public API; `translation/google_translate` and `ocr/google_vision` only get `base_url` (via the vendor's own `client_options={"api_endpoint": ...}` dict param), since google-cloud clients take `timeout`/`retry` per call method, not at construction; `ocr/aws_textract` wires `endpoint_url` + a `botocore.config.Config(connect_timeout=, read_timeout=, retries={"max_attempts": ...})`; `ocr/mistral` mirrors `llm/mistral` exactly (`server_url`/`timeout_ms`, `max_retries` deliberately not forwarded since Mistral's `RetryConfig` is a time-based backoff with no attempt-count knob); `speech_to_text/openai` and `image_generation/dalle` mirror `moderation/openai` exactly; `speech_to_text/deepgram` wires `timeout`/`max_retries` directly (both plain kwargs on `AsyncDeepgramClient`) but not `base_url` (the SDK has no single base-URL kwarg, only a 4-URL `environment` object for REST/websocket/agent endpoints, no faithful 1:1 translation); `vector_store/weaviate` wires `timeout` via `weaviate.config.AdditionalConfig(timeout=Timeout(query=, insert=))`, no `max_retries` (no simple knob); `vector_store/pinecone` and `vector_store/qdrant` only wire `timeout` (both already have a differently-scoped `host`/`url` config field that isn't the same concept as `ClientOptions.base_url`, so `base_url` is deliberately not wired for either); `vector_store/chroma` is left as a fully documented exception (none of its three client constructors expose a timeout/retry kwarg, and its connection target is already modeled as separate `host`/`port` config fields, not a single base_url). Two pre-existing instances of the same "non-secret field wrongly living on `Credentials`/ad-hoc config" bug that Phase A fixed for Ollama were fixed the same way here: `AzureTranslatorCredentials.endpoint` and `WeaviateCredentials.url` both moved off `Credentials` (the providers now resolve `client_options.base_url or from_env(...) or "<hardcoded default>"` themselves), and `MidjourneyConfig`'s ad-hoc `api_url`/`timeout` fields (which predated this split and duplicated what `ClientOptions`/`RequestOptions` now provide) were deleted outright in favor of the inherited fields. `reranking/{huggingface,flashrank}`, `ocr/tesseract`, `speech_to_text/{faster_whisper,whisperx}`, `vector_store/faiss`, and `image_generation/stable_diffusion` are unchanged, still exempt as local/offline compute with no network client. Before that, `core/config.py` gained `RequestOptions` (a `ProviderConfig` subclass adding `timeout: float | None`/`max_retries: int | None`), the per-call counterpart to `core/credentials.py::ClientOptions`. `llm/config.py::GenerationConfig` and `embeddings/config.py::EmbeddingConfig` now inherit it (`RequestOptions, ModelConfig`) instead of hand-declaring `timeout`/`max_retries` inline; this also fixes a real gap, `EmbeddingConfig` previously had `timeout` but no `max_retries`, even though 3 embeddings providers already called `resolve_max_retries` against it. `moderation/config.py::ModerationConfig` also adopted `RequestOptions`, and `moderation/openai/provider.py::OpenAIModeration._client_kwargs()` now actually resolves `timeout`/`max_retries` (previously only read `base_url`). Redundant per-provider re-declarations of `max_retries` that duplicated the new inherited default were removed (`embeddings/openai/config.py`, `embeddings/mistral/config.py`). This is Phase B of the credentials/config cleanup; the remaining 6 network-bound domains (`reranking`, `translation`, `ocr`, `speech_to_text`, `vector_store`, `image_generation`) were deliberately left un-adopted for now: none of their providers currently read `base_url`/`timeout`/`max_retries` at all, so wiring `RequestOptions`/`client_options` into them means writing new per-vendor-SDK plumbing from scratch (verifying each SDK's constructor actually accepts a timeout/retry kwarg), not just relocating existing code the way Phase A/B did, a bigger and separate effort. Before that, `core/credentials.py::ProviderCredentials`/`BaseCredentials` were split into `Credentials` (secrets only, e.g. `api_key`) and `ClientOptions` (non-secret construction-time transport settings: `base_url`, `timeout`, `max_retries`), matching the credentials/client_options split `google-cloud-python` uses rather than lumping both under one "credentials" name. `ClientOptions` is a single, unsubclassed type (its 3 fields mean the same thing for every vendor), unlike `Credentials`, which still gets a per-provider subclass in `integrations/credentials.py` since secrets differ per vendor. Only providers that are network-bound and actually read these fields adopted a new `client_options: ClientOptions | None = None` constructor param alongside `credentials`: `llm/{openai,anthropic,mistral,ollama,huggingface}`, `embeddings/{openai,mistral,ollama,huggingface}`, `moderation/openai`; `resolve_timeout`/`resolve_max_retries` now resolve against `ClientOptions` instead of `ProviderCredentials`. `OllamaCredentials.base_url` (previously a credential despite Ollama having no real secret, just a server location) moved to `ClientOptions`; `OllamaLLM`/`OllamaEmbeddingProvider` now resolve it as `client_options.base_url or from_env("OLLAMA_BASE_URL", "http://localhost:11434")` in the provider itself, since `ClientOptions` no longer carries provider-specific defaults. This is Phase A of a larger credentials/config cleanup; Phase B (the `RequestOptions` extraction described above) has since landed. Before that, `core/interfaces/dataset/base.py::BaseDatasetProvider.load()`/`aload()` were reshaped to take `path: str` as an explicit second positional parameter (like `BaseMediaLoader.load(source, config)` already does), instead of burying it inside `DatasetConfig.path`; `DatasetConfig` now has no required fields, so `HuggingFaceDatasetProvider` gained a `_default_config()` (returning `HuggingFaceDatasetConfig()`) and no longer raises when `config` is omitted. `components/dataset/component.py::Dataset` follows the same shape: since `BaseDatasetProvider.load()`/`aload()` take `(path, config)` as two independent per-call params (not a config that's static per component instance), `Dataset` takes no config in `__init__` and bundles both into its `arun()` input tuple (`DatasetInput = tuple[str, DatasetConfigT | None]`), the same pattern `components/ocr`/`components/speech_to_text` already use for their backends' `(source, config)`/`(audio, config)` shape, not `Loader`'s (constructor-level `self._config`, used when a component's backend config is set once and stays fixed across calls). `evals/cli.py::_load_dataset` updated to the new call shape (`HuggingFaceDatasetProvider[EvalCase]().load(EvalCase, "json", HuggingFaceDatasetConfig(data_files=path))`). Before that, a new `dataset` domain was added end-to-end (`core/interfaces/dataset/{base,config}.py::BaseDatasetProvider`/`DatasetConfig`, `integrations/dataset/huggingface/` wrapping the `datasets` library, `components/dataset/component.py::Dataset`), for generic train/test/eval dataset loading, processing, and batching. Rather than reimplementing Arrow storage, disk-cached `map()`/`filter()` fingerprinting, streaming, and native/stratified splits, the `huggingface` provider wraps `datasets.load_dataset()` and its returned splits' own `map`/`filter`/`iter` methods directly (`huggingface/mappers.py::resolve_splits`, which also handles ratio-based train/test/eval splitting via `Dataset.train_test_split()` when a source has no native splits); the `core/interfaces/dataset` ABC and `components/dataset` wrapper stay free of the `datasets` import, matching the "components delegate to integrations" rule. New `dataset-huggingface` `pyproject.toml` extra. `evals/dataset.py::EvalDataset` was then migrated onto this and, once it became a thin pass-through (its only real value was `from_jsonl`'s convenience and `filter_by_tag`, the latter unused anywhere in the codebase), deleted outright rather than kept as a wrapper: `EvalRunner.arun()` now takes any `Iterable[EvalCase]` instead of the `EvalDataset` type, and `evals/cli.py::_load_dataset()` inlines the JSONL loading (`HuggingFaceDatasetProvider[EvalCase]().load(EvalCase, HuggingFaceDatasetConfig(path="json", data_files=...))[DatasetSplit.TRAIN]`), translating the provider's `ProviderError`/pydantic `ValidationError` into `EvalDatasetError`, which `cli.py::main()` now actually catches (previously nothing did, a malformed dataset crashed the CLI with a raw traceback). `evals/__init__.py` no longer exports `EvalDataset`. This adds a real `datasets` dependency to the evals CLI path, tracked as the new `evals` `pyproject.toml` extra (`agent_platform[evals]`), and `evals/README.md`'s CLI example now installs `--extra evals` alongside `--extra llm-openai --extra dev`. Before that, `components/` and `agents/tools/` were restructured to one directory per unit (`components/<name>/component.py`, `agents/tools/<name>/tool.py`), matching the layout `integrations/<domain>/<provider>/` already used, replacing the old mixed rule where simple wrappers were flat files (`components/embedder.py`) and only complex units got a subdirectory; no per-unit `__init__.py` either, callers import the submodule directly (e.g. `components.embedder.component`), same as integration providers. `components/README.md` and `agents/README.md` were updated accordingly, and tests were moved/renamed to mirror (`tests/components/<name>/test_component.py`, `tests/agents/tools/<name>/test_tool.py`). Before that, two default-value bugs were fixed (`GenerationConfig.temperature` and `DalleConfig.quality` both hardcoded a value that got forwarded/validated unconditionally, overriding vendor defaults or crashing on other models; both are now `None`-by-default and forwarded only when explicitly set) and four domain configs (`clustering`, `vad`, `vector_store`, `ocr`) were cleaned up so shared `core/interfaces/<domain>/config.py` fields only hold what nearly every provider in that domain actually uses, moving or dropping the rest, see `core/README.md`'s "`interfaces/`: The Contract Layer" section for the rule and `git log` for the specifics. Before that, `llm/_base.py::NativeLLMProvider._client_kwargs()` was removed: it was only usable unmodified by 2 of the domain's 6 providers (`openai`, `anthropic`), while `huggingface`/`ollama` overrode it with a different kwarg shape and `mistral`/`google` skipped it entirely, so it wasn't actually a shared shape, just an accidental one; `openai` and `anthropic` now each define their own `_client_kwargs()` inline, matching the pattern the other 4 llm providers (and all `embeddings` providers, which never had a base-level version) already used. Before that, `parse_model_string` was moved out of `core/config.py` into a new `config/model_string.py`: it's DI-wiring logic specific to `Settings`' `"<provider>:<model>"` convention with a single consumer (`config/container.py`), unrelated to `core/config.py`'s remaining `ProviderConfig`/`ModelConfig` pydantic schemas that 14 domain configs subclass; all doc references (`README.md`, `config/settings.py`, the three `integrations/<domain>/__init__.py` comments) and its tests (now `tests/config/test_model_string.py`) were updated accordingly. Before that, `core/tracing.py` was split into vendor-agnostic OTel plumbing (`tracing.py`: `TracingConfig`/`configure_tracing`/`traced_span`/`mark_span_error`) and a GenAI semantic-convention layer on top of it (new `core/genai_tracing.py`: `GenAIAttributes`/`traced_operation_span`/`record_token_usage`); `traced_span`/`traced_operation_span` also switched from `**attributes: Any` to an explicit `attributes: Mapping[str, Any] | None` parameter, since GenAI's dotted attribute keys were never usable as real kwargs, and tool-error span tagging in `agents/tools/registry.py` now reuses the new shared `mark_span_error()` instead of a hand-rolled duplicate. Mapper functions were also split out of provider files across `integrations/`: every provider (or shared base file) with real vendor-type-to-core-schema conversion logic now keeps that logic in a sibling `mappers.py` instead of inline in `provider.py`, see `integrations/README.md`'s "Provider and mapper files" section). `core/errors.py`'s `with_retry()` was also split out into a new `core/retry.py`, since it's a generic backoff/resilience utility (42 call sites across nearly every integration domain) with no relation to `errors.py`'s exception hierarchy/`error_logged`/`catch_noraise`; `errors.py` now holds only error definition and logging concerns, all call sites and the `tests/core/test_errors.py::TestWithRetry` tests (now `tests/core/test_retry.py`) were updated accordingly)

The platform is **structurally complete** at the integration, component, pipeline, agent, and evals layers. The remaining gap is `workflows/`, still an empty scaffold; `api/` has a real FastAPI entrypoint (`api/app.py`) wiring one `ConversationAgent` via `config/container.py::build_agent()`, driven by `config/settings.py::Settings`. That agent already carries `GenerateImageTool`/`TranscribeTool`, not chat only: `Settings.default_llm_model`/`default_image_model`/`default_audio_model` are `"<provider>:<model>"` strings (`config/model_string.py::parse_model_string`) resolved against each domain's `PROVIDER_ALIASES` map (`integrations/<domain>/__init__.py`) by `build_provider`/`build_provider_from_model_string`.

### What is solid

- **Core**, interfaces, schemas, error hierarchy, credentials: complete and stable, including `core/interfaces/classification/base.py` (`BaseClassificationProvider` ABC, added alongside the other domain ABCs)
- **Integrations**, 15 domains with providers: complete (see `integrations/README.md` for the full table). Every provider (or shared base file, e.g. `chunking/langchain_base.py`) that has more than a couple of free-standing vendor-type-to-core-schema conversion functions keeps them in a sibling `mappers.py` rather than inline in `provider.py` (22 per-provider `mappers.py` files across `llm`, `vector_store`, `ocr`, `image_generation`, `speech_to_text`, `clustering`, plus `chunking/mappers.py`); providers with only thin inline conversions (`embeddings`, `reranking`'s network providers, `translation`, `vad`, etc.) were left as-is. This is in addition to the existing domain-level shared conversion modules `ocr/utils.py`, `speech_to_text/utils.py`, and `reranking/scoring.py`. Also including `classification/transformers` (zero-shot via `pipeline("zero-shot-classification")`, consuming the `classification-transformers` extra) and the new `moderation` domain (`openai` via `omni-moderation-latest` + a local offline keyword-rule fallback, sharing `_base.py::NativeModerationProvider` for the network-bound provider, same dual-client shape as `reranking/_base.py::NativeReranker`). Provider SDKs install via per-provider `pyproject.toml` extras (e.g. `llm-openai`, `vector-store-chroma`), not a monolithic dependency list. The `llm`, `embeddings`, `vector_store`, and `reranking` domains (21 providers total, including the new `llm/google`/`embeddings/google` Gemini provider) each call their vendor's native SDK or REST endpoint directly now, no LangChain intermediate; each domain's shared `langchain_base.py` has been deleted along with the `langchain-*` deps it pulled in. `chunking` is the only domain that still has a shared `langchain_base.py`, wrapping `langchain-text-splitters` directly (a genuinely useful splitting library, not a thin pass-through). `llm`, `embeddings`, `reranking`, `translation`, and `moderation` each have a native, non-LangChain shared base instead: `integrations/<domain>/_base.py` (`NativeLLMProvider`/`NativeEmbeddingProvider`/`NativeReranker`/`NativeTranslator`/`NativeModerationProvider`) factors the tracing/retry/token-usage or request/response plumbing that's identical across that domain's providers, so each provider file holds only its vendor-specific client construction and mapping logic; this never crosses domain boundaries (e.g. `llm/openai` and `embeddings/openai` still duplicate their small client-kwargs snippet on purpose, since integrations must stay self-contained per `integrations/README.md`). `reranking`'s local providers (`huggingface`, `flashrank`) and `moderation`'s `local` provider don't use their domain's native base, same reasoning as other local/offline compute being exempt from the retry wrapper. `speech_to_text` has a narrower shared `_base.py::buffered_stream()` (a free async generator, not a provider base class) factoring the client-side windowing loop shared by `whisperx`/`faster_whisper`/`openai`'s `stream()`; `deepgram` is exempt since its streaming is a native socket protocol, not client-side batching. `ocr` and `image_generation` were evaluated for the same pattern and deliberately left without a shared base: vendor-specific response shapes (e.g. OCR bounding boxes) mean a template would add abstraction without removing real duplication. Every provider method that does real work now ships in a sync/async pair (`rerank`/`arerank`, `translate`/`atranslate`, `generate`/`agenerate`, `embed_document`/`aembed_document`, `detect`/`adetect`, `moderate`/`amoderate`), matching how modern provider SDKs ship distinct sync/async clients; streaming methods stay async-only, and `llm`'s `stream()` now also accepts a `tools` param, yielding `ToolCallDelta` fragments on `StreamChunk` (real per-fragment deltas from OpenAI/Anthropic, one whole delta per call from Mistral/Ollama/HuggingFace/Gemini). `llm/openai` and `llm/anthropic` additionally implement `core/interfaces/llm/batch.py::BaseBatchLLMProvider` (`submit_batch`/`get_batch_status`/`fetch_batch_results`), a separate mixin ABC rather than part of `BaseLLMProvider` since Mistral/Ollama/HuggingFace/Gemini have no first-class batch API to implement it against. `vector_store/qdrant` implements `add_hybrid`/`search_hybrid` (dense+sparse hybrid search, fused server-side via Qdrant's RRF `FusionQuery`), paired with a new local `embeddings/bm25` provider (`core/interfaces/embeddings/sparse.py::BaseSparseEmbeddingProvider`, a separate ABC from `BaseEmbeddingProvider` since it returns a `SparseVector` not a dense one) that produces raw term-frequency sparse vectors via feature hashing, no corpus-fit step needed since Qdrant's server-side `Modifier.IDF` handles the weighting; Pinecone hybrid support is an explicit non-goal since Pinecone expects a client-side-fitted sparse encoder, a different stateful shape. `chunking`, `clustering`, `classification`, `loader`, and `embeddings/bm25` (purely local/offline compute, no vendor sync/async split to mirror) are not held to that pairing
- **Components**, `Embedder`, `Chunker`, `Loader`, `Reranker`, `Generator`, `VectorSearch`, `SimilarityScorer`, `EmbeddingClassifier`, `LLMClassifier`, `Dataset`: complete
- **Pipelines**, `pipelines/rag/ingest.py` (loader → chunk → embed via `Embedder` → store, `BaseVectorStore.add()` takes precomputed vectors directly), `pipelines/rag/query.py` (embed query → search → rerank → generate), `pipelines/speech_translation.py` (`SpeechTranslationPipeline.run()`/`.stream()`, audio → STT → translate with streaming support): complete
- **Agents**, `Agent`, `AgentExecutor`, `ConversationAgent`, `ToolRegistry`, `TranscribeTool`, `SearchTool`, `OCRTool`, `TranslateTool`, `ClassifyTool`, `GenerateImageTool`, `SummarizeTool`: complete
- **Evals**, `evals/` package (`EvalCase`/`EvalRunner`/`Scorer`/`EvalReport`, `agent-platform-eval` CLI, golden `ConversationAgent`/`AgentExecutor` tool-selection dataset), Phase 1 of the agents-layer roadmap: complete, see `evals/README.md`
- **Tooling**, mypy and import-linter are wired into CI (`.github/workflows/ci.yml`) alongside ruff and pytest; the layered-architecture and core-isolation rules in AGENTS.md §6 are enforced by `lint-imports`, not just convention; an `evals` CI job runs the golden dataset against a real provider, gated to manual `workflow_dispatch` only (never on push/PR) since it costs real API usage
- **Test suite**, `tests/` (structural + coverage-gate pass done): `pyproject.toml [tool.pytest.ini_options] addopts` enforces `--cov-fail-under=90` locally and in CI (config lives in `pyproject.toml [tool.coverage.*]`, no `.coveragerc`). Mocking goes through the `pytest-mock` `mocker` fixture, not raw `unittest.mock.patch`; every test is auto-marked `unit` via a `pytest_collection_modifyitems` hook in `tests/conftest.py` unless explicitly marked `integration` (currently 0 tests are, the suite is fully mocked); shared helpers live in `tests/helpers/`. See AGENTS.md §3 for the full convention
